# Env 스코프 조회 최적화 기록

작성일: 2026-08-21

## 대상

- 주요 로직: 인터프리터의 변수 조회/대입 경로
- 파일: `src/interpreter.rs`
- 벤치 입력: `notes/bench/scope-lookup-env/scope_lookup_bench.astrn`

## Before

- 측정 바이너리: `./target/release/astron`
- 측정 방식: 동일 입력 10회 반복 실행, 각 실행의 wall-clock time(ms) 기록
- 실행 명령:

```sh
./target/release/astron notes/bench/scope-lookup-env/scope_lookup_bench.astrn
```

- 측정값(ms): `367, 361, 379, 375, 369, 364, 366, 396, 363, 376`
- 평균: `371.6ms`
- 중앙값: `368ms`

## 관찰

- 기존 `Env`는 `Vec<HashMap<String, Value>>` 형태의 스코프 체인을 사용한다.
- `lookup()`과 `set()`이 가장 안쪽 스코프부터 바깥 스코프까지 선형 탐색한다.
- 반복문 안에서 깊은 블록 중첩이 생기면 변수 하나를 읽거나 쓸 때마다 여러 해시맵을 순차적으로 확인하게 된다.

## After

- 측정 바이너리: `./target/release/astron`
- 측정 방식: `before`와 동일
- 측정값(ms): `344, 357, 346, 345, 364, 350, 368, 345, 347, 342`
- 평균: `350.8ms`
- 중앙값: `346.5ms`

## 변경 내용

- `Env` 내부 표현을 `Vec<HashMap<String, Value>>`에서 다음 구조로 변경했다.
- `scopes: Vec<Vec<String>>`
- `values: HashMap<String, Vec<Value>>`
- 변수 선언 시 현재 스코프에 이름을 기록하고, 이름별 값 스택에 값을 push한다.
- 변수 조회와 대입은 이름별 값 스택의 마지막 원소를 바로 읽거나 갱신한다.
- 스코프 종료 시 현재 스코프에서 선언한 이름들을 순회하면서 각 값 스택을 pop한다.

## 결과 요약

- 평균 실행 시간: `371.6ms -> 350.8ms`
- 절대 개선: `20.8ms`
- 상대 개선: 약 `5.6%`

## 해석

- 기존 구조의 병목은 깊은 스코프에서의 반복적인 선형 탐색이었다.
- 변경 후 조회/대입은 평균 `O(1)`이 되었고, 스코프 종료 비용만 해당 스코프의 선언 수에 비례하도록 이동했다.
- 이번 벤치는 의도적으로 깊은 중첩과 반복 조회를 만들었기 때문에, 실제 프로그램에서도 블록 중첩과 변수 접근이 많은 경로에서 같은 방향의 개선을 기대할 수 있다.
